# 分析师交付失败修复（v4）

2026-10-31 从实际失败任务的归档输出和工具证据中复核到三类问题：

- 市场分析输出较长，在 2400 输出 token 上限处截断，JSON 不完整。
- 基本面缺少财报，第三方补数已失败；模型仍引用 missing=true 的财报页，并使用辅助行情凑结论。
- 新闻分析已经取得新闻，但部分 findings 只引用行情，未满足每条结论都需要新闻证据的约束。

三种原因此前统一显示为“分析师证据校验失败”，无法从界面区分。此前合成样本验证也未覆盖实际失败方式。

## 行为

版本更新为 `analyst-agent-v4`。正常提示词要求最多三条结论并限制引文长度，输出上限调整为 3600 token。校验失败后，仅使用已经读取的证据做一次纠错，不再调用工具；仍然使用原有的引用、原文和本职证据校验。纠错也失败时，错误说明具体原因及结论序号。

纠错继承本次分析的 deadline、token 软限制和美元预算。原始输出、原始错误与纠错结果保留在 `agent_artifact.validation_attempts`，已产生的模型调用、用量和费用累计到同一轮记录和执行检查点。不会通过无限重试或忽略校验来生成报告。

数据准备和第三方补数结束后，若该角色本职证据仍为空，直接生成结构化“证据不足”：中性、无 findings、说明缺失原因，不额外调用模型。它不构成可用于决策的完整报告。社交舆情仍按此前约定，无有效样本就跳过。评测配对的两臂使用相同缺失数据规则和输出上限。

同时修正行情文本中的已发现问题：只有一根日线时，不再把开盘价冒充昨收；有成交量但换手率为默认零、或收盘和昨收不相等但涨跌字段均为零时，明确显示字段不可用或不一致，不重新计算并冒充已落库行情。

## 验证范围

- 全仓 `go test ./...` 通过；新增覆盖截断后一次纠错、累计费用与检查点、伪造引用仍被拒绝、无财报不拼接行情、新闻删除辅助行情独立结论的纠错路径。
- 真实 DeepSeek 回归已准备为显式 opt-in 的 `TestLiveAnalystDeliveryRegression`，使用 000547.SZ / 2026-10-31 的数据库数据，只读业务集合，估算准入预算 0.03 美元，最多十次模型请求，报告禁止覆盖。
- 本轮真实模型回归被自动审批拒绝，原因是尚未明确授权将数据库数据发给外部模型；没有执行该调用，也没有生成真实回归通过报告。本地脚本测试通过不能替代这一步验收。

需要重新构建并重启后端，再创建新分析任务，才能使用 v4。已经保存的失败任务不会自动重写。
