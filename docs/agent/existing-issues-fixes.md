# 现有问题修复（analyst-agent-v3）

本次修复现有Agent流程，未引入Research规划或递归研究。

## 决策质量门禁

结构化AnalystReport从Runtime进入运行聚合，和Markdown正文一起保存，决策链返回analystStatus和evidenceVerified。只有至少一份status=complete、SupportVerified=true且存在事实摘录或推断（不能只有假设）的分析师报告可以放行后续研究/交易/风控阶段。partial与insufficient保留供查看，但不能单独放行决策；未放行时返回undecided，并把后续阶段标为skipped。

旧模式的纯文本运行保持兼容；新模式即使输出不合规，也不会因为有正文而被当作可用于决策的分析。该规则是当前最小门禁，不等同于要求所有选中的分析师都完整，也不替代策略自身的证据覆盖要求。

## 逐项证据与取证工具

每个finding须引用本职证据，每个引用须提供evidence_quotes，原文必须逐字存在于实际返回的对应证据中。fact的claim必须直接摘录引用原文；推断和假设分别用inference、hypothesis标注。SupportVerified由系统设置，不信任模型给出的值。

这些规则验证出处和事实摘录，不自动证明任意推断的逻辑或投资判断正确。需要人工/独立评测核验的推断不会被宣称已证明。

冻结工具支持offset、limit（1..3）、document_id，返回next_offset、文档ID、来源、URL（源有提供时）、发布时间、可获得时间及原文。长文拆为可独立取回的片段；K线按完整记录分页，不再直接切断整段JSON。结果太大时缩小本页，元数据仍超预算则明确报错，避免通用截断破坏工具JSON。

背景资料按参考对象与来源保留各来源的最新记录，来源冲突不再被单一参考对象去重吞掉。新闻保留URL并标记规范化内容指纹，供识别精确转载；相同/不同指纹均不能自动证明来源独立性。

快照哈希覆盖本次有界语料；运行artifact只保存实际送给模型的证据页，包括失败前的页，不把未读材料当作已读依据。每个工具语料上限256片段，超过时显式truncated；已有准备阶段的时间窗/条数限制仍适用。

## 评测

基线与Agent采用同一JSON输出与证据校验规则，基线一次内联同一冻结语料，Agent按需查询。两臂各自记录耗时和P50/P95。设定美元预算时，按样本/重复次数给两臂分配相同额度，同时保留整批共享上限；arm_budget_usd写入评测报告，不在后续读取时重算。

AnalystCase可选expected：status、direction、required_claims、forbidden_claims。标注在执行前校验；required/forbidden规则只进行字面匹配，不是通用语义裁判。报告区分契约passed与标注quality_passed，未标注样本不产生质量通过率。存在标注但Agent质量未通过时，CLI保存报告后返回非零退出码。正确返回证据不足可以匹配拒答标注，但不算完整研究。

新增fixtures/contract-regression-v3.json，包含原六角色合成样本及一个明确无资讯的拒答标注。它验证正向链路和拒答计分，不能代替真实历史留出集。

## 检查点与重试

一次任务可以有多个执行尝试：logical_run_id保留任务ID，_id改为UUIDv7执行ID。一个执行的检查点与最终保存使用同一个_id，重试建立新的_id，历史费用不会被覆盖。FindByRunID兼容逻辑任务ID及旧_id；ListAttempts可读取最多100次尝试。历史回测摘要按逻辑任务取最新尝试，仅最新尝试已完成且未失败时计入；未完成检查点不算成功样本。

模型请求前先保存pending状态，返回后保存已知用量，成员提交后再保存完成状态。挂起记录的费用与最终成员费用在聚合内转移，不重复累计。数据库不可用时，前置检查点失败会阻止继续发起模型请求；关闭轨迹仓储的部署仍保持原行为。

保存由运行根统一提供一致快照，并在仓储一次原子替换整份文档。每次执行串行写检查点，事务/存储细节不泄漏到应用或实体，无子记录仓储。

进程在厂商响应前退出时仍无法知道实际账单，此时保留pending/unknown_usage，而非虚构费用为零。本次没有实现自动续跑或自动对账；恢复执行产生新的尝试ID，旧尝试保留。

## 空快照分页误报内部错误

已修复 `total=0` 后请求 `offset=1` 被当作分页越界，并在工具回灌时显示“服务内部错误”的问题。非负 offset 到达或超过末页时，返回有效的空页，保留真实 total，并明确返回 `has_more=false`、`next_offset=null`；空语料保持 `missing=true`，非空语料的末页不会被误标为源数据缺失。

负 offset、无效 limit、未知 document_id 和非法 JSON 参数使用原有 INVALID_ARGUMENT 错误，回灌模型时提示修正参数，不将参数错误解释成数据缺失。冻结检索工具采用相同规则。真正的内部错误仍隐藏技术细节，并在服务端日志记录原始原因及工具名。未改变全局错误脱敏规则。

新增回归覆盖空新闻/空行情分页、末页后的重复读取、极大 offset、参数错误的模型反馈、检索分页及内部错误脱敏。此修复不补充新闻或行情：`total=0` 仍仅说明本次冻结快照没有符合条件的记录，资料是否未入库、被日期过滤或准备失败需另查对应任务的数据准备记录。运行轨迹继续由聚合根统一管理并通过原仓储原子保存，无跨聚合实体共享、无事务句柄向上传递。

## 行情快照缺失与重复调用

行情快照和日线分别入库。分析准备阶段的 K 线回源不会自动创建完整行情快照，而冻结工具也不会在调用时重新拉取行情，因此原先可能已有日线、`get_quote` 却一直返回缺失。

现在优先使用符合标的及分析日期的真实行情快照；没有时，以已准备的最近一根有效日线提供价格摘要，返回 `data_kind=daily_kline`、实际交易日、数据来源、复权标记及 `missing_fields`。仅复制已有 OHLC、成交量和成交额，不构造完整 Quote，不计算涨跌幅、PE/PB 或换手率，也不把缺失字段补成零。复权价格明确不能用作未复权现价或执行价；历史分析不能读取未来记录。摘要与引用作为原始证据随运行轨迹保存，后续读取不重新推算金额。

若行情快照和符合条件的日线都没有，仍返回 `missing=true`、`retryable=false`，并记录未查到、空记录、读取失败或记录不符合分析范围等原因。此时需先完成行情同步/归档准备，再启动新分析；反复调用同一冻结工具不能补数。

运行时在首次确认冻结工具的整个语料为空后，将它从后续工具声明中撤下。模型仍请求它时复用原空结果，轨迹及决策链接口以 `reused=true` 标识；若一轮只剩此类重复请求，下一轮强制收尾。检索无匹配仅针对当前关键词，不会撤下 `search_evidence`，实时工具同样不套用冻结缺失规则。独立任务仍保留各自的数据快照，不共享或持久化临时工具缓存。

## 本地缺失后自动回源，以及 BSON 丢失代码的根因

分析的数据准备现在先读取并过滤本地记录。行情、财务、资讯或社交样本仍缺失时，通过已注入的 StockService 一次提交缺失种类，使用配置中的第三方降级链补齐、校验并保存，再生成冻结证据；不需要用户手动先同步。普通分析、独立分析师和数据库 Research 均走这条链路。冻结 JSON 评测继续离线，不触发第三方。

补数并发上限为 2，每种数据最多一轮业务请求，单种超时 10 秒、整批 20 秒；各源原有的限速、网络重试和降级仍生效，且受父 context 截止时间约束。K 线的原有回源也增加 20 秒上限。某一种失败不取消已经成功补齐的其他种类。空新闻、空财务结果不再阻止尝试下一个已配置源。自动补数排除 Mock，避免把真实数据缺失悄悄替换为模拟材料。

行情读取的另一个真实根因是 Mongo DTO 使用了未导出的匿名 `codeColumns` 内嵌结构：BSON 编解码会忽略这块字段，导致读到的 Quote/News/Kline 等代码为空，随后被分析的标的匹配过滤器拒绝。现已将 stock 与 agent 仓储内部的内嵌类型改为导出的 `CodeColumns`，保留原 BSON 字段名，并用实际 BSON 编解码回归覆盖所有行情类 DTO 及运行轨迹。映射仍只在仓储 DTO 内进行，不向上层泄漏 DTO。

旧记录缺少 market 或 symbol 保留明确交易所后缀时，在读取边界恢复可明确识别的规范代码；不会把一个明确有效但不同的市场强行改写。`002131.SZ` 在周六 2026-10-31 分析时允许使用周五 2026-10-30 的行情，拒绝未来日期。缺失的历史行情只调用支持 as-of 的接口；Tushare 已接入带截止日期的 daily 查询，其他只有“最新行情”能力的源不会被用于填历史快照。新闻、社交按市场日期边界过滤，财务必须有当时已披露的公告日。第三方成功但归档保存失败的数据不会进入本轮冻结证据。

每种补数保存 provider、status、message、count、rejected、saved、duration_ms，随 AnalysisContext 在原运行文档中原子保存；工具证据携带 preparation，决策链接口提供 dataPreparations，数据准备全失败时错误消息也会概述补数结果。状态区分 fetched、empty、failed、unsupported、disabled。无跨聚合实体共享、无新子项仓储，事务仅在原仓储内部；金额直接保存数据源返回值，后续读取不重新推导。

目前配置的东方财富/Tushare/Finnhub 没有实现社交舆情接口，因此缺失社交样本会明确显示“当前配置的数据源不提供社交舆情接口”，不会用新闻冒充社交或无限重试。已预留可选社交能力端口；需要真实社交样本时仍需接入有权限的数据源。新闻搜索命中也不代表已覆盖全部公告、研报全文或行业一手资料。

2026-10-31 直接探测东方财富公开接口：002131.SZ 返回一条 2026-10-30 行情及近月 10 条新闻，最近一条发布时间为 2026-10-30 09:43:34 +08:00。探测没有调用 LLM、没有写业务数据库，结果见 [真实数据源探测](data-source-probe-002131-20261031.json)。

本轮全仓 `go test ./...` 通过。新增覆盖空库回源、已有数据不重复回源、回源并发与取消、保存失败不使用未归档数据、能力缺失与源故障区分、空源继续降级、周末采用前一交易日行情，以及实际 BSON 编解码保留股票身份。测试使用本地模拟数据源；上述公开接口探测单独记录，不等同于对业务数据库执行了回填。

## 社交舆情是可选分析

数据准备后没有符合标的和分析时点的有效社交样本时，直接跳过 sentiment 分析师，不调用 LLM，不生成“中性/证据不足”的情绪报告，不登记为分析失败，也不把可选社交缺失放进其他分析师的全局缺失警告。仅有新闻不能替代社交样本；拿到真实有效的社交样本后恢复正常分析。

普通分析、独立分析师、Agent/基线配对评测和 Research 均采用相同规则。跳过记录由 AnalysisContext 聚合根持有并通过原仓储原子保存；决策链接口暴露 skipped/skipReason，阶段结果提供 skippedAgents，计费保持零模型调用。跳过不计入成功人数；其他有效分析不受影响。若只选择情绪分析且无样本，分析阶段及后续决策步骤均跳过，不再为零报告启动交易流程。

Research 中跳过的社交子问题不会生成正文段落、审查缺口或补证任务；全部子问题都跳过时，研究状态为 skipped，不继续审查和汇总。分析师与 Research 评测单列 skipped，标注可使用 expected.status=skipped；“跳过”不混入完整报告数或失败数。其他分析的证据门禁不变，没有可用分析时不会生成交易指令。无跨聚合实体共享、无新增子项仓储或向上传递的事务句柄。
